# StickerEmojiBot

Телеграм-бот, который собирает **наборы анимированных кастом-эмодзи** из
250 встроенных TGS-шаблонов: пользователь выбирает шаблоны и шрифт,
присылает надпись или SVG-логотип, оплачивает звёздами — и получает
готовый набор.

## Сценарий

```
/start → меню: 👤 Профиль · ✨ Создать эмодзи · 💬 Поддержка
      → выбор набора шаблонов (Основной — 250 шт.)
      → 🎲 случайно  или  ✋ выбрать самому
         │
         ├─ 🎲 случайно
         │    1. витрина шрифтов: 6 примеров, по одному эмодзи на шрифт,
         │       надпись — юзернейм бота, поверх водяной знак
         │       (можно загрузить свой .ttf/.otf — он встанет седьмым)
         │    2. надпись текстом или логотип файлом .svg
         │    3. сколько эмодзи собрать (кнопки или своё число)
         │
         └─ ✋ выбрать самому
              1. страницы по 12 шаблонов, отметки галочками,
                 либо диапазон текстом: «1-12, 20-25, 7»
              2. витрина шрифтов (та же)
              3. надпись или логотип
      → финальное превью: все выбранные эмодзи одной сеткой,
        тип набора (💎 премиум-эмодзи или 🖼 обычные стикеры) и
        куда добавить — в новый набор или в уже существующий
      → оплата: ⭐️ счёт Telegram Stars или 💼 списание с баланса
        (1 звезда за штуку)
      → сборка набора и ссылка t.me/addemoji/… либо t.me/addstickers/…
```

На любом шаге можно вернуться и перевыбрать шаблоны, шрифт, надпись или
тип набора — превью и цена пересчитываются.

**Пополнение криптой.** Если в `.env` задан `CRYPTO_TOKEN` из
@CryptoBot (Crypto Pay → Create App), в профиле появляется второй способ
оплаты — через @CryptoBot или @send. Бот выставляет счёт в USDT по
курсу из `CRYPTO_RATE` (по умолчанию 1 USDT = 100 звёзд), даёт кнопку
оплаты и сам зачисляет звёзды, когда деньги пришли.

Вебхук не используется намеренно: он требует публичного HTTPS-адреса,
которого у бота на обычном хостинге нет. Вместо этого неоплаченные счета
опрашиваются раз в 15 секунд, и есть кнопка «Я оплатил» для нетерпеливых.
Зачисление защищено от повторов на уровне базы: закрыть активный счёт
удаётся только одному из двух путей, поэтому звёзды не начислятся дважды.
Без токена способ просто не показывается, остальной бот работает как был.

**Баланс.** В профиле есть пополнение звёздами: 50/100/250/500/1000 или
своё число. Когда на балансе хватает, на превью появляется кнопка
списания — заказ уходит в сборку без счёта. О каждой покупке и каждом
пополнении админам приходит уведомление.

**Куда добавлять.** По умолчанию бот заводит новый набор, но если у
человека уже есть набор нужного типа, куда весь заказ помещается
(в Telegram до 200 штук), его можно выбрать — эмодзи допишутся туда.

**Обязательная подписка.** Каналы добавляются в админке: `/admin` →
**📣 Обязательная подписка** → «Добавить канал». Принимается `@username`,
ссылка `t.me/…` или пересланный из канала пост — последнее работает и для
закрытых каналов. Каналов может быть несколько, человек должен быть
подписан на все; проверка целиком выключается одной кнопкой.

Чтобы проверка работала, **бота нужно назначить администратором канала** —
иначе Telegram не отдаёт список подписчиков. Бот сообщает об этом сразу
при добавлении, показывает состояние каждого канала по кнопке «Проверить
права» и пишет его в лог при запуске. Если прав нет, люди проходят
дальше: живой бот важнее строгости, а причина видна в логе. Проверка
стоит на `/start` и на входе в создание — отписаться можно в любой
момент. Админы её не проходят.

**Админам.** Сборка бесплатна: на финальном превью вместо оплаты стоит
кнопка «🎁 Собрать бесплатно». Права проверяются в обработчике заново —
на подделанный callback_data кнопка не сработает.

## Установка

```bash
pip install -r requirements.txt
```

Скопируй `.env.example` в `.env` и заполни:

```
BOT_TOKEN=123456:ABC...        # от @BotFather — обязательно
SUPPORT_CONTACT=@your_support  # куда ведёт кнопка поддержки
ADMIN_IDS=123456789            # у кого работает /admin
REQUIRED_CHANNEL=@your_channel      # первый канал подписки, дальше — в админке
PRICE_PER_EMOJI=1              # стартовая цена; дальше меняется из панели
```

Разогреть превью каталога (необязательно, но первое открытие станет быстрее):

```bash
python tools/build_previews.py
```

Запуск:

```bash
python bot.py
```

## Команды

| Команда | Кому | Что делает |
|---|---|---|
| `/start`, `/menu` | всем | главное меню |
| `/admin` | админам из `ADMIN_IDS` | админ-панель |
| `/give @username 100` | админам | начислить звёзды на баланс |

## Админ-панель

`/admin` открывает панель на инлайн-кнопках. Роутер админки закрыт
фильтром по `ADMIN_IDS` целиком, поэтому чужому нажатию некуда попасть
даже по угаданному callback.

**📊 Статистика** — всего пользователей, эмодзи, наборов, выданных
заказов и звёзд; срезы за сутки/неделю/месяц; хвосты — незакрытые счета
и сбои сборки.

**👥 Пользователи** — список от новых к старым с постраничной листалкой,
поиск по id или части ника. Карточка показывает даты, счётчики, баланс,
наборы со ссылками и последние заказы; оттуда же — выдать звёзды,
написать человеку от лица бота (сообщение уходит копией, как есть) и
заблокировать или разблокировать.

**💼 Выдача звёзд** — с главного экрана панели строкой `@username 100`
либо кнопкой в карточке. Отрицательное число снимает с баланса, ниже
нуля баланс не уходит. Ник ищется **точным** совпадением: `@ivan` не
попадёт в `@ivanov`. Получателю приходит уведомление, остальным
админам — запись о том, кто и сколько выдал.

**🧾 Заказы** — все заказы с суммой и статусом (`не оплачен` / `оплачен,
собирается` / `выдан` / `сбой сборки` / `возвращён`). В карточке — состав
шаблонов, шрифт, содержимое, id платежа и **возврат звёзд** через
`refundStarPayment` с отдельным подтверждением: отменить возврат нельзя.

**📢 Рассылка** — админ присылает любое сообщение (текст, фото, что
угодно), панель показывает число получателей и просит подтверждение,
затем рассылает копией с прогрессом. Заблокированные исключены,
остановившие бота считаются отдельно от ошибок, на `429` рассылка ждёт
столько, сколько просит Telegram.

**⚙️ Настройки** — цена за эмодзи и режим техработ. Меняются на ходу,
пишутся в базу и переживают перезапуск; при техработах создание эмодзи
закрыто для всех, кроме админов. Список админов задаётся только в `.env`.

**🖼 Шаблоны** — сколько файлов на диске, каких номеров не хватает, и
проверка: прогон подстановки текста по всем шаблонам со списком тех, что
не собираются.

Уведомления о покупках и пополнениях приходят всем, кто указан в
`ADMIN_IDS`: кто заплатил, сколько, чем (счётом или с баланса) и номер
заказа.

## Как это работает внутри

В шаблонах слово `TEXT` нарисовано **векторными контурами**, а не текстовым
слоем — в формате TGS текстовых слоёв нет. Движок находит это слово по
геометрической подписи букв, удаляет его контуры и на их место кладёт
контуры новой надписи, взятые из TTF/OTF через `fontTools`. Собственная
трансформация группы, цвет и вся анимация при этом не трогаются — поэтому
надпись живёт ровно там же и так же, как оригинальная. SVG-логотип встаёт
в ту же зону; без подписи зона добирается по высоте до квадрата, иначе
логотип вписался бы в узкую строку и вышел в разы мельче.

Готовый файл проверяется перед отправкой: валидный gzip, валидный JSON,
обязательные поля Lottie, размер до 64 КБ (лимит Telegram). Все 75
шаблонов проходят проверку с надписью в 20 символов; самый тяжёлый
результат — около 47 КБ.

Заказ пишется в базу **до** выставления счёта, а его id уходит в payload
платежа: оплата приходит отдельным апдейтом, и после перезапуска бота
состав набора берётся из базы, а не из потерянной сессии. Списание с
баланса идёт одним UPDATE с условием `balance >= amount` — двойное
нажатие «оплатить» не уводит баланс в минус.

Превью в каталоге показывают не слово `TEXT`, а юзернейм бота: человек
видит ровно то, что получит. Кадр для превью выбирается не наугад —
шаблон прогоняется по девяти точкам таймлайна и берётся самый
наполненный, иначе анимации с уходом в конце давали пустую плитку.

## Оформление: всё меняется из бота

`/admin` → **🎨 Оформление**. Ни файлов на сервере, ни перезапуска —
владелец правит бота кнопками в чате, и правки переживают передеплой.

**✏️ Текст меню.** Присылаешь сообщение — оно становится текстом меню
как есть. Жирный, курсив, ссылки, цитаты и премиум-эмодзи сохраняются:
пишешь сообщение так, как оно должно выглядеть, никаких тегов знать не
нужно. Подставляются переменные `{name}`, `{bot}`, `{templates}`,
`{price}`, `{fonts}`.

**🖼 Медиа меню.** Присылаешь фото, гифку или видео — встаёт над текстом
меню. Файл сохраняется у бота, а не хранится как `file_id`: при смене
токена картинка не потеряется.

**🔘 Кнопки и цвета.** Список всех кнопок бота. У каждой меняется:

* подпись — своим текстом (переменные вроде `{amount}` бот подсказывает
  и просит не терять);
* цвет — 🔵 синий, 🟢 зелёный, 🔴 красный, 🎨 «по теме» или без цвета;
* премиум-эмодзи — присылаешь сообщение с нужным эмодзи, бот сам достаёт
  из него id.

**🎨 Тема** перекрашивает одним нажатием все кнопки, у которых выбран
цвет «по теме». **👁 Показать меню** рисует результат так, как его увидит
пользователь. **♻️ Сброс** возвращает всё к стандартному виду.

Чего Telegram не умеет: форматирования и премиум-эмодзи внутри самой
подписи кнопки — подпись это простая строка. Поэтому премиум-эмодзи
ставится отдельным полем и рисуется перед подписью.

Правки лежат в `branding.json` в папке данных. Файл можно готовить и
руками — образец со всеми ключами лежит в `branding.example.json`, — но
это необязательный путь: всё то же самое делается кнопками.

## Добавить свои шаблоны

1. Положи `.tgs` в `templates/` под следующим номером (`076.tgs` и дальше).
2. Подними `TEMPLATE_COUNT` и границу набора в `config.PACKS` в `config.py`.
3. Проверь, что движок видит в нём надпись:

```bash
python -c "import tgs_engine as e; print(len(e.build_emoji(76, 'ТЕСТ', 'stolzl')))"
```

Если вылетает `Шаблон не содержит заменяемой надписи TEXT` — в шаблоне нет
распознаваемого слова `TEXT`, такой файл не подойдёт.

## Ограничения Telegram

* Ставить кастом-эмодзи в сообщения могут только пользователи с **Premium**;
  создавать наборы через бота может любой.
* В одном наборе — до 200 эмодзи; за раз в `createNewStickerSet` уходит 50,
  остальные доклеиваются по одному.
* **Файлы уходят вложением прямо в запрос набора.** Отдельный
  `uploadStickerFile` на каждый .tgs не делается: `createNewStickerSet`
  принимает до 50 файлов одним multipart. Заказ на 50 штук — это один
  вызов вместо пятидесяти одного.
* **Создание новых наборов ограничено отдельно и жёстко.** Telegram
  может ответить `retry_after` в несколько минут и повторять тот же
  ответ на каждую попытку — это лимит на бота целиком, а не темп
  запросов. Пауза длиннее 90 секунд считается таким лимитом: заказ не
  объявляется сбоем, а откладывается со статусом «оплачен». Бот сам
  повторяет сборку до трёх раз, когда пауза истечёт, и держит общий
  счётчик ожидания — пока он идёт, к Telegram не обращается вовсе, чтобы
  не жечь попытки. Кнопка «Повторить сборку» остаётся на случай, если
  бот перезапустили и отложенная задача потерялась. Дозапись в существующий набор под это ограничение
  не попадает, поэтому бот предлагает её как обходной путь.
* **Лимит «8 за 4 минуты» считается по стикерам, а не по запросам.**
  Это ключевая деталь: в `createNewStickerSet` можно вложить до 50 штук
  одним вызовом, и по числу запросов это единица — но Telegram считает
  содержимое. Пачка больше окна упирается во флуд-контроль сразу и
  навсегда, сколько её ни повторяй. Поэтому первый вызов берёт ровно
  `config.CREATE_BATCH` (по умолчанию 8) штук, а счётчик окна платит за
  каждый вложенный стикер. Заказ на 12 штук идёт около 4 минут, на 50 —
  около получаса.
* **Максимум заказа — 50 штук, и это не случайное число.**
  `createNewStickerSet` забирает до 50 стикеров одним вызовом, а каждый
  следующий идёт отдельным обращением под лимит «8 за 4 минуты». То есть
  заказ до 50 в новый набор собирается мгновенно, а 200 штук ждали бы
  больше часа после оплаты. Потолок задан в `config.MAX_ORDER`; если
  поднять его, включите в админке «Большой заказ: паками по 50» —
  тогда заказ раскладывается по наборам, каждый из которых снова один
  вызов.
* **Лимит на запись в наборы считается по аккаунту, для которого набор
  создаётся, а не по боту.** Это видно по логам: два разных токена
  упирались в одну и ту же паузу, пока заказы шли на один и тот же
  тестовый аккаунт. У обычного покупателя счётчик свой и пустой,
  поэтому проверять бота нужно с постороннего аккаунта — иначе меряешь
  не бота, а собственную исчерпанную квоту.
* **Лимит на создание наборов может закрыться надолго** — не на минуты,
  а до суток, если ботом много тестировали. Тогда бот не откладывает
  заказ в никуда: если у человека уже есть набор нужного типа с местом,
  эмодзи уходят туда, и заказ выдаётся. Новый набор ждёт только тот, у
  кого своего набора ещё нет.
* **Дозапись в существующий набор идёт по одному стикеру**, поэтому
  50 штук туда — около 25 минут. Бот показывает это время до оплаты, а
  по умолчанию предлагает новый набор — быстрый путь.
* **Запись в наборы: 8 обращений за 4 минуты.** Новый набор — это один
  вызов на первые 50 штук, поэтому он собирается сразу. Дозапись в
  существующий — вызов на каждый стикер, то есть 8 штук за окно: 30 штук
  идут около 12 минут, 50 — около 25. Новый набор до 50 штук собирается
  сразу, свыше 50 — остаток по одному. Бот ждёт окно сам (`_WriteLimiter`),
  показывает остаток времени и предупреждает об этом ещё до оплаты.
  Ловить 429 постфактум нельзя: именно так заказ молча обрывался на
  восьмом эмодзи.
* Один файл `.tgs` — до 64 КБ.
* Возврат звёзд возможен в течение срока, который держит Telegram
  (`refundStarPayment`), — кнопка возврата в карточке заказа дёргает его.


## Мини-приложение (v2.3.0)

Telegram Web App внутри бота: четыре вкладки в чёрно-сером оформлении.

| Вкладка | Что внутри |
|---|---|
| **Создать** | надпись, шрифт, тип набора, шаблоны (случайно или вручную), превью, оплата |
| **Магазин** | все шаблоны, сортировка «Новые / Популярные / Старые», поиск, фильтры, живая анимация, добавление своих `.tgs` |
| **Профиль** | баланс и пополнение, промокод, кристаллы и рефералы, «Мои наборы», поддержка |
| **Прочее** | Premium, описание, число шаблонов и цена эмодзи |

**Запуск.** Telegram открывает Web App только по HTTPS, поэтому нужен
публичный адрес. В `.env` добавьте:

```
WEBAPP_URL=https://ваш-домен.example      # публичный HTTPS-адрес
WEBAPP_PORT=8080                          # порт сервера (или PORT от хостинга)
WEBAPP_SUPPORT=@apfov                     # контакт поддержки внутри приложения
PREMIUM_PRICE=200                         # цена премиума, ⭐️
PREMIUM_DAYS=365                          # срок премиума
FREE_ORDER_LIMIT=10                       # лимит эмодзи в заказе без премиума
```

Сервер стартует вместе с ботом (`python bot.py`), домен/туннель должен
вести на `WEBAPP_PORT`. Без `WEBAPP_URL` мини-приложение выключено, бот
работает как раньше. Для проверки на своём ПК подойдёт `cloudflared tunnel --url http://localhost:8080`.

**Оплата.** Баланс в звёздах, кристаллы (5 💎 = 1 эмодзи) или счёт Telegram
Stars. Пополнение — звёздами или криптой (если задан `CRYPTO_TOKEN`).

**Кристаллы и друзья.** Ссылка `t.me/<бот>?start=ref_<id>`; 5 💎 за друга,
ступени «итого»: 5 друзей — 40 💎, 15 — 100 💎, 30 — 250 💎 (разница с
обычной наградой выдаётся бонусом). Награда приходит, когда друг прошёл
проверку подписки. Значения — `REFERRAL_*` в `config.py`.

**Админка** (`/admin`): «🎟 Промокоды» (создание, вкл/выкл, удаление),
«🧩 Шаблоны юзеров» (скрыть/показать), «🎨 Оформление» — приветствие с
премиум-эмодзи, фото/гиф/видео и цвет/эмодзи кнопок, в том числе новой
кнопки «Мини-приложение». Команды: `/crystals @user 50`, `/premium @user 30`.
